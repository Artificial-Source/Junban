## Database blocker closure evidence

- `P4-DB-001` and `P4-DB-002` are fixed. Route-local limits preserve the ordinary ceiling while 8 MiB transfers and generated backups pass; private disk staging and bounded copies replace payload-sized body aggregation. Focused evidence: `body_limits_are_route_specific_and_transfer_uploads_pass_the_ordinary_ceiling`; `generated_backup_restore_streams_above_the_ordinary_body_ceiling`; staged-operation cancellation/exclusivity tests; accepted cgroup data-operation evidence.
- `P4-DB-003` is fixed. Apply-plus-rollback failure durably writes and fsyncs `recovery-required.json` before returning `CatastrophicRestore`; both startup and `ProfileOwner` fail closed on that marker even when SQLite remains openable. The lock-retaining recovery router starts before normal admission, and the already-running catastrophic boundary permits only authenticated restore plus recovery/health endpoints. A successful durable recovery restore clears the marker and still requires process restart. Focused evidence: `apply_and_rollback_failure_persists_recovery_across_owner_reopen`; `catastrophic_runtime_boundary_accepts_authenticated_recovery_restore`; `catastrophic_marker_for_openable_database_survives_restart_into_recovery_only_process`.
- `P4-DB-004` is fixed. Authenticated sync state exposes the required epoch; event catch-up rejects mismatched and future cursors; the React client fetches the epoch and performs an authoritative resync before reconnect. Evidence: `sync_state_is_authenticated_and_sse_rejects_invalid_reset_cursors` and the focused client epoch-reset tests.
- `P4-DB-005` is fixed. Restore compares every user table, index, and trigger against a freshly migrated canonical schema and rejects hostile/altered objects before maintenance. Evidence: `restore_preflight_rejects_noncanonical_user_schema_without_mutating_live`.
- `P4-DB-006` is fixed. Recovery replacement writes an owner-only, atomically replaced and parent-fsynced versioned cutover marker containing candidate filename, rollback directory, length, SHA-256, schema version, and event epoch before the first rename. Startup sees it before any normal SQLite open; reconciliation validates candidate identity, preserves rollback material, completes any missing live/WAL/SHM rename and candidate install, durably validates the installed database, then clears markers. Focused evidence: `recovery_cutover_reconciles_every_rename_boundary_without_empty_profile`; `interrupted_recovery_cutover_is_reconciled_before_process_can_open_sqlite`.
- `P4-DB-007` is fixed. Export keyset-pages 128 tasks at a time, batches catalog/tag hydration, writes a private staged artifact incrementally, and streams cleanup ownership with the response. The accepted 10,000-task evidence records 506.48 ms p50 / 510.13 ms p95 JSON export and 8.6406 MiB maximum export cgroup peak.
- `P4-DB-008` is fixed. Import inverse material records import-owned projects/tags and atomically rejects later ownership conflicts. Evidence: `import_undo_removes_only_import_owned_catalog_resources`; `import_undo_rejects_reused_catalog_resource_without_partial_deletion`; `import_late_catalog_validation_failure_is_atomic`.
- `P4-DB-009` is fixed. Framing, hashes, integrity, foreign keys, canonical schema, typed rows, settings, and inventory all validate before maintenance or stream invalidation. Evidence: `invalid_backup_preflight_keeps_maintenance_and_active_streams_untouched`.
- `P4-DB-010` is fixed. SSE drain fails closed and restore cancels and awaits/aborts the owned reminder coordinator before cutover. Evidence: `restore_forwarder_timeout_is_fail_closed_without_cutover`; `restore_drains_streams_and_requests_then_stops_owned_coordinator`.
- `P4-DB-R1` is fixed. Restore preflight keyset-pages typed row loaders and streams relationship/control rows, validates domain values and serialized event/receipt-response/undo payloads under existing byte bounds, and checks graph, settings, schema-history, app-state, activity, retained-event continuity, and event-head invariants before maintenance. Typed undo task collections (`RestoreImport`/`RestoreClosure`/`RestoreTasks`/`ReverseCompletion`) now enforce unique task IDs and the `MAX_BULK_IDS=500` ceiling; `ReverseCompletion` rejects source/generated identity overlap; post-image validation bounds the unique union of present tasks, absent task IDs, and order keys and rejects present/absent contradictions. Focused evidence: `restore_preflight_rejects_domain_invalid_and_malformed_serialized_rows`; `restore_preflight_rejects_restore_tasks_inverse_over_bulk_ceiling`; `restore_preflight_rejects_duplicate_and_overlapping_undo_task_identities`; expanded `invalid_backup_preflight_keeps_maintenance_and_active_streams_untouched` (empty title, malformed event, malformed receipt response, and malformed inverse).
- The exact-working-tree database specialist closed `P4-DB-001` through `P4-DB-010` and `P4-DB-R1`, approving the database code gate subject to measured performance. The 10,000-task `junban-phase4-data-v1` run then passed exact export/restore integrity, cleanup, 6.6562 MiB median / 6.8516 MiB maximum post-restore warm memory, and 25.2617 MiB maximum peak. Its preceding 32.8086 MiB failed run is retained; cgroup diagnostics identified three simultaneous SQLite file-cache copies, and the reviewed Linux-only rollback-cache advice fixed the root cause without changing rollback durability. `DB-RST-PCACHE-001` (an initial macOS cfg error in that optimization) was fixed by restricting libc and `posix_fadvise` to Linux; the specialist approved the corrected delta.

The frontend correctness/accessibility review closed `P4-UI-001` through `P4-UI-005` on the exact working tree. A narrow re-review closed `P4-UI-R1` and approved the Phase 4 UI gate, including the remaining `P4-UI-006` consumption paths.

The legacy Phase 4 authority manifest separately verifies all ten immutable input PNGs and records their provenance.

Focused context/DataTab tests, production-build dogfood, and narrow UI re-review closed the finding. Evidence: `phase-4-dogfood/report.md`.
