## Permanent SDK-owned artifact tooling

`junban-plugin-sdk` exposes and tests this typed pipeline through the `junban-plugin-artifact` Rust CLI. Before any signing ceremony, the exact built tool and pipeline must pass their focused checks:

1. **Source manifest parse/validate.** Parse a versioned, `deny_unknown_fields` author manifest. Source fields may omit only values derived from exact component/public-key bytes, such as `component_sha256` and `publisher.key_id`.
2. **Runtime manifest derivation.** Derive the existing fixed-order `RuntimeManifest`, validate it through the SDK, serialize it once with the existing SDK canonical runtime-manifest authority, and reparse/reserialize for exact equality. No JavaScript tool, shell script, or second JSON/JCS implementation may canonicalize runtime manifests.
3. **Package pack/sign.** Inspect the exact component imports/exports/profile, derive the runtime manifest, form JBP1 with the existing SDK `pack_package` authority, read an external owner-only Ed25519 key file without printing it, and immediately public-verify the output.
4. **Index pack/sign.** Build JRI1 entries from already verified JBP1 identities plus typed presentation metadata, sort and validate with the SDK `RegistryIndex` authority, serialize that typed index once, sign the JRI1 domain with an external owner-only root key file, and immediately public-verify it. There is no second JRI canonicalizer and no index built from unchecked handwritten package hashes.
5. **Public-only verification.** Given only source manifests, components, JBP1 files, JRI1, public keys, and the generated include table, independently rederive runtime manifests, verify package/index signatures and hashes, validate registry/package agreement and imports, and reject extra/missing/misnamed blobs or include entries.
6. **Permanent checker.** A repository command wraps public-only verification and cleanly fails on source-manifest, component, package, index, public-key, include-table, or expected-hash drift. CI and contributors run this command without signing access.

The signing subcommands must reject private-key paths beneath the checkout, target directories, package-manager caches, or evidence output; reject permissive Unix metadata and fail closed on Windows until owner-only DACL verification is reviewed; avoid key bytes in arguments, environment, stdout/stderr, errors, panic text, logs, diagnostics, or artifacts; and zero temporary key buffers where the selected library permits. They never generate repository keys or auto-resign after drift.

Required focused tests cover source-manifest unknown/duplicate/derived-field conflicts; runtime-manifest byte determinism; JBP1/JRI1 golden and negative vectors; wrong key/mode/ACL/path; source/component/package/index/include drift; missing/extra blobs; public-only operation with signing files unavailable; Linux/macOS/Windows path behavior; and stable secret-free failures.

## External one-time signing ceremony

The release maintainer owns two external one-time Ed25519 private-key files: a reference publisher key and a release-scoped registry root key. They are created and held outside the checkout, build roots, caches, profiles, logs, CI, and release output. CI and ordinary contributors never receive them.

The ceremony runs in this exact order:

1. Start from the reviewed clean candidate inputs and pinned toolchains. Record the candidate commit/tree and tool binary hash without recording secrets.
2. Build all three exact components and run source, package, import/export, behavior, and reproducibility prechecks.
3. Use `target/release/junban-plugin-artifact package sign` with the external publisher key file to derive each canonical runtime manifest and produce the finalized JBP1 files. The Rust packer is the only canonicalization authority.
4. Public-verify each JBP1, record its component/runtime-manifest/package hashes and size, and place it at `plugins/registry/sha256/` under its lowercase SHA-256 digest plus `.jbp`.
5. Use `target/release/junban-plugin-artifact index sign` with the external root key file to derive the typed JRI1 entries from those verified packages, produce the finalized `plugins/registry/index.jri`, and write only the root public key to `plugins/registry/root-public-key.bin`.
6. Generate the product include table from the verified index and exact content-addressed blobs. Rebuild the product so signed artifacts and include bytes are part of the candidate.
7. Make both private-key files unavailable to the verification process. Run the permanent checker, SDK verifier, product registry/install checks, cross-platform public matrix, and artifact/hash reproducibility checks using public material only.
8. Inspect tracked/untracked files and captured output for private material. If any public-only check, registry agreement, build, behavior, or secrecy check fails, cancel the ceremony, discard every derived signed/public artifact, and restart later with new keys.
9. Only after all public-only checks pass, destroy the external one-time private keys and record only non-secret custody/destruction attestation. Never claim recoverability; a future Junban release uses a new release-scoped root/publisher ceremony.

The ceremony commits no private key, seed, mnemonic, encrypted key backup, raw key command, or secret-bearing environment capture. A public key, key fingerprint, signature, and artifact digest are intentionally public.

## Cross-platform acceptance matrix

Linux, macOS, and Windows jobs each run from the same candidate and public artifacts:

- build and test `junban-plugin-sdk`, `junban-plugin-host`, and the thin artifact tool;
- build the Rust references with pinned Rust 1.93.0, `wasm32-wasip2`, and exact `wit-bindgen`; require fresh/retained byte equality only on canonical Linux x86_64/amd64, while macOS, Windows, and other architectures must complete the locked optimized build and verify the retained public artifacts without cross-host byte equality;
- build the TypeScript reference with the exact pinned Node/npm toolchain, then remove build-time Node from the runtime process boundary;
- rederive each runtime manifest from its source manifest and component and public-verify every JBP1, JRI1 entry, package path, root key, expected hash, and generated include entry;
- install and execute Pomodoro, automation, and TypeScript references through the real optimized server/host path;
- prove expected imports, grants, stale fences, trap containment, shutdown, disable, and no orphan host;
- prove no Node process exists in the runtime process tree.

Linux x86_64/amd64 is the canonical Rust-reference byte authority, and Linux cgroup v2 is the only memory authority. Noncanonical hosts report both fresh and retained identities and the actual match while requiring successful locked builds and retained public package/signature verification; cross-host byte inequality is informational. macOS and Windows results establish authoring, public package/signature verification, product execution, lifecycle, and cleanup portability; they do not substitute platform memory values into Linux budgets. Private signing is intentionally not part of the Windows matrix: `junban-plugin-artifact` fails closed there because no reviewed owner-only DACL verifier exists. Windows public verify/build/runtime support remains required and unaffected.

## Performance authority

### Common rules

All three reports use the same clean candidate, optimized binaries, production `dist/`, and exact signed packages/index/include table. The default report uses five matched base/candidate pairs; the Rust and TypeScript reports use five fresh candidate samples each. Linux cgroup v2 must be available; `memory.swap.max=0`; file-only reclaim uses `memory.reclaim` with `swappiness=0`; swap use must remain zero. Each sample uses a fresh leaf cgroup and fresh profile, settles by observed readiness rather than sleeps, records full-lifecycle `memory.peak`, and proves cleanup.

The measured cgroup contains only the release `junban-server` and, when active, its real sibling `junban-plugin-host`. Build tools, the driver, and any TypeScript build-time Node process remain outside the cgroup and finish before sampling. Runtime process-tree inspection must reject Node, Vite, browsers, package managers, and unexpected children. At most one plugin runtime is loaded at a time in the package-specific scale-1 reports.

Every report records exact commit/tree, dirty status, source/lock/tool hashes, `dist/` hash, server/host/tool binary hashes and sizes, component/source-manifest/runtime-manifest/JBP1/JRI1/root/include hashes, OS/kernel/cgroup/controller data, CPU/memory/host-contention snapshot, Rust/Node/pnpm/jco/componentize-js/Wasmtime versions as applicable, exact command, sample values, process trees, swap, profile/package sizes, workload counts, cleanup, and checker result.

Latency records include startup-to-health, verify, install, compile, enable, first call, warm operations, disable, and cleanup where applicable. Report raw values and p50/p95 observations, but do not apply or imply a latency pass ceiling.

### Default/no-plugin report

Run five interleaved matched Phase 6-base and Phase 7-candidate samples using the exact frozen Phase 1 workload. The candidate must satisfy:

- maximum warm cgroup current ≤24 MiB;
- maximum cgroup peak ≤32 MiB;
- candidate median warm growth over the matched base ≤`max(15%, 1 MiB)`;
- exactly one server process, no plugin host, no Wasmtime construction, no Node, and complete cleanup.

This report cannot include an installed/enabled reference and cannot borrow an active-plugin budget.

### Rust package report

Run five fresh samples. Each sample executes two sequential segments, never with more than one loaded runtime:

1. Install, verify, grant, and enable Pomodoro. Set/read its fixed test settings. Execute exactly 100 numbered warm rounds covering its declared command, settings read, KV transition/readback, declarative view/status render, and declared action; verify each returned authority and final state. Disable it, wait for host cleanup, and prove no Pomodoro runtime remains.
2. Install, verify, grant, and enable automation. Deliver exactly 100 numbered subscribed source events. For every event verify its declared deterministic AppService effect, cursor terminalization, and exact operation/receipt replay without a second effect. Disable it and prove final host/profile cleanup.

Gate the maximum observed cgroup current and full-lifecycle peak across every Pomodoro, between-segment cleanup, automation, and final-cleanup observation in all five samples:

- maximum current ≤91,678,720 bytes;
- maximum peak ≤131,328,000 bytes.

The report also fails on wrong corpus count/digest, duplicate/missing effect, cursor/replay mismatch, simultaneous loaded runtimes, swap, runtime Node, unexpected process, orphan, or cleanup failure. Scale 4/16 remains a separate functional/admission/cleanup check and informational memory record; it cannot replace or relax this package-specific scale-1 gate.

### TypeScript package report

Run five fresh samples using only `plugins/reference/import-typescript/`. For each sample install, verify, grant, enable, and invoke its one declared existing bounded bulk-task command/action corpus; verify the exact affected-task bound, AppService receipt/event, replay, contribution fence, disable, and cleanup. Do not deliver plugin events and do not report or imply TypeScript event evidence.

Gate all five samples at:

- maximum current ≤692,418,560 bytes;
- maximum peak ≤806,824,960 bytes.

The report also fails on wrong bulk corpus/result, swap, runtime Node, unexpected process, orphan, or cleanup failure. TypeScript values are never merged into default or Rust results. Scale 4/16 remains functional/informational only.

## Clean candidate and evidence invalidation

- finalized signed JBP1 blobs, JRI1, root/publisher public material, expected hashes, and generated product include table;

Create a local candidate commit/tree so `git status --porcelain` is empty, build all optimized artifacts from it, and bind every report to that commit/tree and exact bytes. Preliminary dirty runs may guide development but are labeled non-authoritative and are not copied into accepted result fields.

After measurement, append only bounded result JSON/Markdown, outcome/ledger status, review disposition, and final-CI identifiers. Such result-only documentation does not invalidate evidence when it exactly binds the measured candidate commit/tree and artifact hashes and changes no behavior, executable input, lock, generated contract, signed artifact, include table, checker, protocol, schema, corpus, budget, or validation rule.

Any post-measurement change that can affect behavior, binaries, package/component/runtime-manifest/JBP1/JRI1 bytes, public keys, include table, tool/checker decisions, workload/corpus, protocol, budget, locks, generated contracts, process ownership, or measurement collection invalidates and reruns every applicable package, dogfood, cross-platform, validation, and performance report. When uncertain, invalidate.

After accepted results and review, squash all Phase 7 work to the single required phase commit without changing candidate executable/artifact inputs. Re-run permanent public checks and full final CI on that exact squash head. If the squash or result append changes an executable/artifact input hash, the applicable authoritative evidence must be rerun. ## Evidence schema expectations

Each machine-readable result uses a versioned, fail-closed schema and includes:

- `protocol`, `schema_version`, `authority` (`preliminary` or `authoritative`), and `budget_passed`;
- candidate commit/tree, final-head commit when known, clean-tree proof, exact command template, start/end timestamps, host contention, and toolchain provenance;
- all executable/source/lock/generated-contract/component/manifest/package/index/key/include/checker hashes and sizes needed to recreate the decision;
- one object per sample and workload segment with cgroup path/controllers, `memory.current`, `memory.peak`, swap before/after, RSS/PSS/process tree, operation counts/digests, observed latencies, profile size, and cleanup;
- explicit assertions for no runtime Node, expected server/host counts, at-most-one loaded runtime in package-specific scale-1 samples, exact corpus counts, receipts/events/cursors/replay, no orphan, lock release, and artifact public verification;
- the applicable byte budgets and computed maxima/medians without unit ambiguity;
- public ceremony artifact identities and non-secret custody/destruction attestation, never private material;
- checker version/hash, result-document hash, review finding status, and exact final-CI run/job identifiers once available.

The checker recomputes aggregates and gates from raw samples. A missing field, nonzero swap, dirty authoritative candidate, hash mismatch, secret marker, unexpected process, incomplete corpus, failed cleanup, or ambiguous unit fails closed.

## Security, secrets, and runtime Node

- Signing establishes publisher/index integrity, not plugin safety; strict grants, import validation, Wasmtime isolation, runtime limits, application validation, and stale fences remain mandatory.
- Private keys and operator/automation bearers never enter SQLite, source manifests, runtime manifests, packages, index metadata, profiles, environment captures, command arguments, logs, diagnostics, screenshots, evidence, CI, or release artifacts.
- Public fingerprints, signatures, and hashes are not secrets, but errors remain bounded and do not reflect package/component bytes.
- Node/pnpm/jco/componentize-js are author/build/test tools for the TypeScript component and React frontend only. Runtime evidence rejects any Node executable in the measured process tree.
- The exact build-only `componentize-js → weval → decompress@4.2.1` advisory remains an explicit threat-model disposition and the package-local audit does **not** pass. There is no AOT path, no untrusted archive input, and every build version is pinned. Reopen before enabling AOT, accepting untrusted build/archive input, changing the pinned chain or invocation, or when the advisory/patch status changes. This does not suppress or weaken the mandatory root `pnpm audit --audit-level high` gate.
- The permanent checker and all runtime package/index verification are Rust and require no Node.
- Windows private signing fails closed until a reviewed owner-only DACL verifier exists; public verification and Windows build/runtime acceptance remain supported.
- Complete backup excludes package files and signing material; restore retains only the schema-v7 inactive authority already frozen in the schema contract.
